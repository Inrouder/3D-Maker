## Automatisierte Prüfung

- `npm test`: 15 Tests für primitive Geometriemaße, Breitenänderung eines gedrehten Körpers und gültige/ungültige Projekte.
- `npm run build`: TypeScript und Vite-Produktionsbuild.
- `npm run test:browser`: Chromium-End-to-End-Tests, Mindestfenster 960 × 640; gedrehtes Objekt bearbeiten, Schnittmodus wechseln, Werkzeugleiste scrollen, fehlerhafte Datei laden, Dialog-Shortcuts, aktuellen Projektnamen speichern, gruppiertes Objekt auf Boden setzen und Sprach-Fallback.
- `git diff --check`: Whitespace-Prüfung.
- `npm audit --omit=dev --audit-level=high`: Produktionsabhängigkeiten.

Browser lokal vorbereiten: `npx playwright install chromium`, anschließend `npm run test:browser`. Alternativ einen vorhandenen Chromium mit `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium` auswählen. Hier wurde vorhandenes Linux-Chromium mit Software-WebGL verwendet.

Ein Lockfile und `npm ci` in CI machen Abhängigkeitsauflösung reproduzierbar. Geometrie-/Projektdateitests laufen im Web-Build-Job mit.

## Grenzen und offene Punkte

- Windows-Portable-EXE und Electron-Updateablauf wurden hier nicht ausgeführt. Der Electron-Binärdownload scheiterte mit ECONNREFUSED; Web-Abhängigkeiten wurden mit `ELECTRON_SKIP_BINARY_DOWNLOAD=1` installiert. Windows-Paketierung verbleibt im vorhandenen Windows-CI-Job.
- Vite meldet weiterhin ein großes JavaScript-Bundle (>500 kB); Code-Splitting wäre eine separate Optimierung.
- Nicht einheitliche Gruppenskalierung gedrehter Mitglieder kann Scherungen erzeugen, die das aktuelle Position/Drehung/Skalierung-Modell nicht verlustfrei darstellen kann. Dafür ist eine eigene Modellierungsänderung mit Geometrie-Backen erforderlich.
- Boolean-/Schnittfunktionen sind geometrieabhängig. Keine vollständige Prüfung aller Importmeshes, nicht-manifolder Flächen, Gewindepassungen oder sämtlicher CSG-Randfälle.
- Keine automatische Veröffentlichung oder Versionsanhebung: Änderungen sollen zuerst im Pull Request geprüft werden.
